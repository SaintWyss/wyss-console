# 29 — Product capability preservation

A check that the security decisions of this set did not quietly remove something the final
product is meant to do. One row per capability the owner named. It says nothing is built that
is not: `[R]` marks what exists, and every other row is design.

Written after the reconciliation of 2026-10-13 (the protected restoration vault,
[27](27-PROTECTED-RESTORATION-VAULT.md); the concurrency contract,
[28](28-CONCURRENCY-AND-FILESYSTEM-INTEGRITY.md)). By the author; unreviewed.

## 1. Labels

| Label                       | Means                                                                                           |
| --------------------------- | ----------------------------------------------------------------------------------------------- |
| **Built**                   | Exists and is tested `[R]`                                                                      |
| **Designed**                | Interfaces, states, failure behaviour and tests are written; nothing left to decide or find out |
| **Designed, unverified**    | The same, resting on a provider behaviour or a number nobody has observed                       |
| **Blocked by evidence**     | Cannot be finished on paper until a named observation exists                                    |
| **Blocked by decision**     | Cannot be finished on paper until the owner takes a named decision                              |
| **Not yet designed enough** | Requirements and options exist; contracts, states, threat model or tests do not                 |

A capability can carry more than one. None of these labels authorises building anything.

## 6. What this matrix does not show

The audit of [31](31-PLANNING-COVERAGE-AUDIT.md) (2026-10-13) checked this matrix against the
owner's scope and found three capabilities narrowed or never stated without a record: switching
the model of a running session (now DN-38), restoring agent panes with the workspace (now
DN-36), and orchestration beyond handoff, which has no requirement (31 §4). They are not rows
here because none of them is a security decision; they are recorded there.

- That any design here is right. The independent review rejected the set it read; the
  corrections and everything written on 2026-10-13 are unreviewed.
- That any provider behaves as the documents say.
- That a capability labelled "designed" would survive its own implementation unchanged.
