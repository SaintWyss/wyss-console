## 3. Wire types and validation contract (proposed schema v1)

All records use `schema_version: 1`, require known field sets (Rust `serde(deny_unknown_fields)` where appropriate), byte limits, canonical deterministic serialization for persisted digests, and a distinct `B1TaskId` type (UUID, not interchangeable with `ManagedSessionId`/`TerminalId`). Snapshot authorization and content identity are not mere bearers that any same-UID actor may forge to create strong A.

| Type                    | Mandatory fields                                                                                                                                                                                                               | Acceptance and semantic limits                                                                                                                                                                                                                                          |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `B1SourceSelectionV1`   | task_id; repo_id; base_commit_oid; repo_object_format (`sha1`/`sha256`); admitted_overlay[]; policy_id + policy_sha256; identity of owner selection; issued_time; finite limits                                                | Owner selected exact base and each overlay. Keep source repository path private in UI/diagnostics; never interpret client-supplied arbitrary filesystem path as access authority. Object hashes must match chosen Git format and be read under safe Git-object contract |
| `B1OverlayEntryV1`      | path_bytes; operation (`add/modify/delete/rename`); entry_kind (`regular/symlink`); expected_base_entry_oid or explicit absent; content_sha256+size+mode or deletion tombstone; rename_from path where needed; reviewed_digest | Include **staged/unstaged modified tracked files**, deleted/renamed and selected untracked. No implicit import. Rename is an exact delete+add semantic pair, not a filesystem operation on an untrusted path. No special files/gitlinks                                 |
| `B1AdmissionRecordV1`   | task_id; selected base; policy fingerprint; approved overlay hash; exact admitted tree fingerprint; generation; record_revision; content budgets                                                                               | Written by trusted admission component only after immutable capture and content review. A changed source after capture cannot mutate this record; any mismatch before launch aborts                                                                                     |
| `B1WorkspaceReceiptV1`  | task_id; generation; source_manifest_sha256; task_fs_id; mount_policy_digest; preexec_profile_digest; runtime_fingerprint; checked_at                                                                                          | Prove task-specific isolated writable object set and required ABI/FD/caps; never use inode number alone as durable authority                                                                                                                                            |
| `B1ExportRecordV1`      | task_id; generation; base_admission_hash; entries[] (typed path, operation, kind, mode, size, sha256, inert symlink target); exporter_digest; source_tree_hash                                                                 | Produced after verified quiescence by exporter in its own sandbox. No arbitrary path strings, executable instructions, socket/FIFO/device records, Git config or unsafe symlink traversal                                                                               |
| `B1QuarantineReceiptV1` | task_id; expected_generation; source_base_oid; admission_hash; export_hash; result_store_ref; CAS_revision; result_tree_oid; risk_flags[]; status = PENDING                                                                    | Independent object store/quarantine ref; publish once by CAS, complete and recoverable. Does not change source .git/working tree; does not itself authorize integration                                                                                                 |
| `B1FailureV1`           | task_id; stage; stable_error_code; action_required; cleanup_status; correlation_id                                                                                                                                             | No secret bytes, auth headers, private paths or raw hostile content in logs. Stable error codes; no silent success state on partial publication                                                                                                                         |

**Path format:** proposed wire representation is canonical URL-safe base64 without padding of _Git relative raw pathname bytes_; decode before checking. Reject empty, leading `/`, NUL, empty/`.`/`..` components, alternate-root traversal, `.git` control paths (including platform/casefold ambiguities), duplicates/colliding normalized names on destination, Gitlink mode 160000, special nodes and unsupported entries. Display text is diagnostic only; path authorization operates on exact bytes. Non-UTF8 names must be preserved as bytes or rejected visibly until supported; never silently substitute Unicode strings. A symlink target is **data**, with independent rejection for absolute/outside-root/ambiguous targets on import, and inert output on export. Git nested metadata must not run code.

**Content snapshots:** select/review exact file bytes _before_ execution and bind them to admission. From a mutable source, stage private content and rehash; a writer racing the read yields either one exact captured version explicitly reviewed or a deterministic rejection. Two different source epochs must never appear in one authorized snapshot. An authorized selection can contain harmful bytes; admission prevents _unselected_ content exposure and external inode aliasing, not arbitrary transformed-secret classification.

**Canonical validation details required before code:** exact max path/depth/record/total bytes; legal Git modes; object format; collision policy; idempotence keys; stable field ordering and cryptographic digest domain separation. Do not assume JSON textual key order is canonical: hash a versioned deterministic binary encoding or a published canonical-json scheme with test vectors. Every digest embeds domain/version/task or structure identifier to prevent cross-purpose reuse.

## 4. State machine and failure semantics

`CREATED → SELECTING → CAPTURED → ADMITTED → MATERIALIZED → CONFINED → RUNNING → QUIESCING → FROZEN → EXPORTING → VALIDATED → PENDING`

Terminal states: `REJECTED`, `FAILED_CLEAN`, `FAILED_CLEANUP_UNVERIFIED` and `BLOCKED_UNSAFE`. Any transition to `PENDING` requires stable admission fingerprint, verified working-set independence, a completed restricted launcher receipt, no remaining writer, validated export, and atomic quarantine CAS.

- `SELECTING` cannot launch; source contents not admitted by merely opening a folder dialog.
- `CAPTURED` is an exact finite private snapshot; `ADMITTED` records user-selected bytes and policy. If a selected file changes between preview and authorization, regenerate preview before accepting.
- `MATERIALIZED` must have independently allocated mutable inodes; no live-tree lower layer. Launcher rejects unexpected host mounts before `CONFINED`.
- `CONFINED` must be checked **before** any untrusted runtime instruction. Failure to obtain Landlock ABI, namespace, PTY permissions, cgroup/process-tree/FD closure needed by profile ⇒ `BLOCKED_UNSAFE` (do not retry with wider grants).
- `RUNNING` includes only B1 tree. Timeout/cancel must move through `QUIESCING` and wait for verified full stop or mark `FAILED_CLEANUP_UNVERIFIED`.
- `FROZEN` output is no longer writable by B1. If write quiescence cannot be demonstrated, never export.
- `EXPORTING` reads through a constrained exporter; malicious FIFO/socket/devices/links are errors, not data blindly followed.
- `VALIDATED` uses a second trusted quarantine-boundary verification (object bytes, typed path, mode, digest, tree/base). `PENDING` is final B1 success; _not_ integrated.
- A crash between staging/publish steps must recover to an unambiguous state: no partial result masquerades as `PENDING`; incomplete task storage is garbage-collected only by exact task identity after processes are accounted for. Retries use idempotent task/gen/revision and never silently supersede a different owner snapshot.

Representative stable errors (no path/secret payload): `ADMISSION_UNAUTHORIZED`, `BASE_OID_INVALID`, `SNAPSHOT_STALE`, `INPUT_KIND_UNSUPPORTED`, `SOURCE_COLLISION`, `HARDLINK_OR_ALIAS_UNSAFE`, `CAPTURE_CHANGED`, `ISOLATION_UNAVAILABLE`, `PREEXEC_VERIFICATION_FAILED`, `TASK_TREE_NOT_QUIESCED`, `EXPORT_NODE_UNSAFE`, `EXPORT_DIGEST_MISMATCH`, `QUARANTINE_CAS_CONFLICT`, `QUARANTINE_RECOVERY_NEEDED`, `PROVIDER_AUTH_UNSUPPORTED`, `PROVIDER_EGRESS_UNPROVEN`. Unknown/unhandled errors fail closed; logs report stage/code, not content.

## 5. Minimum OS sandbox spec: candidate rights not proof

On verified native CachyOS, a rootless launcher is preferred. Spawn parent/pre-exec shim is trusted **outside** the worker-controlled code. Worker gets only reviewed RO runtime and mandatory policy, new RW task-local project, minimal fake auth, private fake inference and necessary PTY/stdio. No `HOME`, user/keyring/runtime directories, host containers, host filesystem, control IPC, X11 or user D-Bus mounts; no inherited authority/ambient descriptors. `no_new_privs=1`, capability reduction, mount/PID/network namespace view, verified Landlock rules and FD closure must be inspected before provider exec.

For the synthetic starting profile, require **at least Landlock ABI 7** only for rights explicitly supported at that version; **never** treat ABI 7 as pathname Unix socket protection (kernel documentation introduces the relevant capability at ABI 9). Linux mount namespace visibility and FD/control-channel closure are separate requirements. A missing required OS primitive or cgroup delegation must yield a reported block; do not loosen rights. Strip unnecessary `MAKE_FIFO`, `MAKE_SOCK`, device creation and arbitrary `REFER` unless positive tests justify each one.

Process supervision must demonstrate no descendant retains writer/mount access before export. A PID list of direct children, single `wait()` or revoked terminal viewer is not sufficient. Treat memory/storage/process exhaustion and deliberate cancellation as negative test cases, without modifying real systemd services or Docker.

## 6. Export/quarantine and Git safety contract

- Exporter opens within its own restricted mount view, anchored to known directory FD(s); use `openat2` with `RESOLVE_BENEATH`, `RESOLVE_NO_SYMLINKS`, `RESOLVE_NO_MAGICLINKS`, `RESOLVE_NO_XDEV` where applicable, plus `O_NONBLOCK` and verified `fstat`; assess fallback only after a new security review, never silently. Symlinks are represented as inert typed targets using `readlinkat` without traversing them.
- Do not run `git status/diff/commit` under untrusted B1 `.git` from a privileged U broker; disable Git configs/filters/hooks/alternates/replacements. Compare typed content against the admitted base snapshot within a restricted verifier.
- Persist result blobs first inside independent quarantine storage; validate object byte digests and paths; fsync as needed; publish the task result by CAS exactly once, then mark `PENDING`. If crash/CAS collision occurs, leave a recoverable non-success receipt. The result store may use Git object format, but cannot be the original repository's `.git` or `refs`: existing U project and HEAD remain unchanged.
- Security classifications for `.github`, `.vscode`, `.claude`, `.codex`, executable files, `AGENTS.md`, `CLAUDE.md`, `Makefile`, `package.json` scripts, `.husky`, `.gitmodules`, `.lfsconfig` and `.gitattributes` are **advisory flags** for owner U review, not a way to execute or suppress hostile bytes. A Git ref does not authorize merge.
- Explicit U integration is separately authorized and outside this task/phase; a user manually merging may still execute untrusted scripts through hooks/CI/editors. Do not advertise safe automatic integration.

## 7. Preimplementation engineering choices, observable and bounded

**Test-profile proposed budgets** (provisional thresholds for independent P2 review **before** CG-14 is run; not measured results): per-source-input 2 MiB, admitted source total 16 MiB, max 2,048 paths, path component ≤255 bytes, depth ≤32, task-local private tmpfs limit 64 MiB/4,096 inodes, task process cap 16, FD cap 64 per process, per-test-case timeout 20s, total suite cap separately fixed. Initial CG-14 RSS/PTY p95 numeric limits must be determined from safe fixture baseline _prior to the acceptance run_ and versioned with the profile; **cannot mark PASS while unset**. Larger repositories need later measured alternative substrate; do not equate baseline test budgets with final product scalability.

Plan a config-and-policy manifest with platform requirements (kernel, Landlock ABI, bwrap, cgroup availability) and a static runtime-loader allowlist of versioned executable/library identities. Report known unsupported features as errors, not as implicit U-mode fallback. Freeze identity/generation independent of PID; keep source storage and worker runtime distinct. Use deterministic test vectors for canonical path encoding, Git entry modes, overlay selection, status transitions and CAS conflict.

**Do not invent a protected approval principal:** this is a scoped same-user B1-local capability architecture. `A` against compromised unrestricted U is still blocked under [47](47-CACHYOS-DOCKER-PRIVILEGE-AND-SANDBOX-DECISION.md).
