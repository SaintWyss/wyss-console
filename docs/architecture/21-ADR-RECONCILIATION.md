# 21 — ADR reconciliation

> **2026-10-22 consolidation:** this document retains dated design/evidence and detailed
> contracts. Its present-tense status/decision tables describe their stated baseline,
> not necessarily current implementation. Read the [current product set](../product/README.md),
> [verified gaps](../product/implementation-status.md) and [requirement crosswalk](../product/traceability.md)
> first. F8 is active P2/V8, ADR0051 Accepted, cap1; P1 remains available. New product
> direction does not supersede accepted security ADRs or turn proposed tests into PASS.

ADRs 0001 to 0028 against the complete design of this set. ADR 0028 already holds a
compatibility matrix for its own decision (`0028`, section "Compatibility with ADRs 0001 to
0027") `[R]`; this document goes further: it looks at every later phase too, and says which new
ADRs the roadmap needs. **No ADR is changed by this set.** Where one should change, the change
is listed in §4 as a decision to take.

Basis of reading: the sections listed in ADR 0028 (`0028`, paragraph "Read directly for this
matrix") `[R]`, re-used; plus, for this set, ADR 0002 `:28-73`, 0005 `:47-56`, 0008 `:78-100`,
0012 `:104-131`, 0015 `:40-62` and `:134-148`, 0016 `:36-66`, 0018 `:110-127`, 0026 `:26-60`
and 0027 in full. The long ADRs (0017, 0018, 0021, 0023, 0025) were not re-read line by line.

## 3. Where this set finds ADR 0028 itself in need of a decision

ADR 0028 is accepted and is not edited by this set. Three of its statements need a decision,
and each now has a proposed ADR that names the provision, says why it changes and gives the
words that replace it.

1. **Restoration data and ADR 0003 (DN-01).** ADR 0028 classes ADR 0003 as "superseded in one
   area", keeps the bytes of parked entries in the Console's private state, says they "may still
   hold a secret", and keeps per file "the restorable entries it last observed" (`0028` §7 and
   the row for 0003) `[R]`. The owner's policy of 2026-10-12 forbade treating that as permission
   to store secrets; his decision of 2026-10-13 allows a protected private backup, with security
   controls and informed consent. Read together, they are
   [ADR 0029](../adr/0029-secrets-restoration-data-and-configuration-persistence.md),
   **Proposed**, second draft:

   | Provision                                                          | Fate under ADR 0029, if accepted                                                                                                                          |
   | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | ADR 0003 `:69-70`, no secret in durable storage                    | Stands everywhere, with one named exception: the vault (ADR 0029 §1, exact wording)                                                                       |
   | ADR 0028, row for 0003: "superseded in one area"                   | Kept, and made exact: the area is the vault                                                                                                               |
   | Decision D5: private local backups with content                    | **Stands, strengthened**: encrypted, consented, minimised, used on the third rung only                                                                    |
   | ADR 0028 §7: a private directory, files readable by the user alone | Strengthened: encryption with a key held outside the directory                                                                                            |
   | ADR 0028 §7: fields an adapter classes as secret are never kept    | **Replaced for vault records**: an exact restoration needs the entry's own bytes (Q11)                                                                    |
   | ADR 0028 §7: last-seen restorable entries per file                 | **Replaced**: hashes and keyed digests. What it gave by default is given by choice: an encrypted recovery copy of entries the user selected (Q4; 27 §3.6) |
   | ADR 0028 §7: export and import                                     | Kept as a requirement; designed; deferred (DN-29)                                                                                                         |

   Two of those rows change something ADR 0028 granted, Q4 and Q11. The owner gave his position
   on both on 2026-10-13: a metadata-only index with an opt-in recovery copy, and the complete entry where an exact restoration requires it. His positions are not the acceptance of ADR 0029: until an ADR on the subject is
   accepted, F2a may not start.

2. **Concurrent writers (DN-21).** ADR 0028 §8 says a provider writing between the last check
   and the rename "is detected on read-back and recoverable from the backup". Neither half
   holds: a rename replaces the provider's write and reads back exactly as planned, and ADR
   0028's own §7 copies no whole file. [ADR 0030](../adr/0030-corrections-to-adr-0028.md),
   **Proposed**, replaces the sentence and excludes a plain rename. It does not choose the
   protocol: the candidate is [07 §5.4](07-CONFIGURATION-ENGINE.md), its contract and its
   limits are [28](28-CONCURRENCY-AND-FILESYSTEM-INTEGRITY.md), and the choice is DN-21.

3. **What the native confirmation protects (DN-22).** ADR 0028 §5 says the backend's check
   "protects the user's configuration from a compromised page and from a slip". The page can
   already write into a terminal (`src-tauri/capabilities/main.json` `[R]`; ADR 0005), so a
   compromised page does not need the configuration commands. ADR 0030 replaces the sentence:
   the dialog prevents a slip and prevents the configuration commands from applying an
   unconfirmed plan; it is not a boundary against code in the page. No permission or capability
   is changed by that correction.

Nothing else in ADR 0028 was found to conflict with this set.

## 5. What must never be done to reconcile documents

- An accepted ADR is not rewritten to look as if it had foreseen a later decision.
- A security guarantee is not relaxed because a newer document reads more conveniently
  without it (D10).
- A sentence of an ADR that no longer holds is named, with the place where it stops holding
  and the decision that ended it. ADR 0028 does this for four sentences; this document adds
  the ones that later phases will end (§1, last column).
