## 1. Owner-confirmed product decisions, 2026-10-14

- **O-1 ACCEPTED (B1 only):** a restricted worker edits a disposable isolated workspace. Its result is always **pending/quarantined**. No automatic writeback, merge, checkout, update of `HEAD` or mutation of the user's live working tree by B1 or its broker. Integration, if chosen, is a distinct deliberate U-mode action, not a B1-local security guarantee.
- **O-2 ACCEPTED:** the owner explicitly selects the repository identity, pinned base Git commit object ID (OID), policy and exact admitted content for each B1 task. A commit/OID/hash authenticates _identity_, not owner intent or admissibility. The trusted admission component records the reviewed selection and verifies the materialized bytes. An approval in a same-UID/X11 session is **not** a nonforgeable human signature against compromised U.
- **O-3 ACCEPTED WITH EXTENSION:** owners may explicitly include **modified tracked files without commits**, staged and unstaged edits, deletions, renames, and untracked files, by reviewing a typed per-task change set. Do not require a commit, and do not silently ingest the whole live working tree. The default additional-file allowlist is empty. Each included path and its exact bytes/type/mode/base identity must be frozen and validated.
- **B1/U split remains frozen:** B1 is a lower-trust automated worker; U is a direct native unrestricted agent/owner tool and is outside B1 containment. Managed M, trusted approver A and planner P remain distinct under 47/49 and accepted ADRs. This proposal does not claim host-global approval integrity or resolve rootful Docker delegation.

The owner authorized **documentation and planning**, not actual B1 implementation, privileged configuration, real provider/credential access, or ADR approval.

## 2. Threat model and security claim

**In scope:** hostile worker B1 and descendants; attacker-supplied repository bytes and metadata; accidental aliases prepared by same-user tooling; symlink/hardlink/ancestor tricks at import or export; broker confused-deputy paths; ordinary concurrent legitimate project edits; bad lifecycle and inherited FD/IPC paths. Treat prompts, plugins, hooks, generated files, result manifests and worker-owned Git metadata as untrusted.

**Outside B1-local guarantee:** a compromised unrestricted U/LP4 agent, host-root/Docker-root delegation, hostile kernel or trusted launcher/broker compromise, strong human consent, and arbitrary data voluntarily admitted by the owner. An U process able to rewrite the admission authority cannot be secured merely through B1's namespaces. Those host-global blockers remain `BLOCKED_ADMIN_DELEGATION` and `BLOCKED_TRUST_BOUNDARY`.

**Precise protected-data statement (RV-1):** forbid filesystem _aliases, capabilities and ambient paths_ that give B1 access to objects outside the independently materialized authorized workspace. It is impossible to prove that a permitted byte sequence never contains a copy or transformation of an external secret. Admissibility is based on explicit authorization of source content, not magical content classification. A known-secret digest denylist may detect selected accidents but is **defense in depth only**, never the security boundary. A hash or OID on its own does not authorize bytes.

## 3. Trust/data flow (candidate, subject to verification)

1. **Owner selection (U/Console):** choose source repository and pinned base OID. Review an explicit typed overlay of locally modified tracked files, staged/unstaged variations, deletes/renames, and individually selected untracked files; present affected paths, sizes, content identity and policy. Admit no incidental `.env`, credentials, caches, sockets, foreign mounts, or home files. Authorization is a task-scoped record; no implicit "all changed" without review.
2. **Trusted admission record:** bind task ID, project identity, base OID, accepted overlay entries, exact hashes, path/type/mode/link target, policy version, content budgets and intent. Record immutable bytes or a stable private copy; prove that each returned byte matches the _authorized_ reference, not just a forged manifest. If source mutates mid-capture, deterministically obtain one exact authorized version or reject; never mix epochs.
3. **Restricted materialization:** consume verified Git object content and exact authorized overlays with neutral Git configuration and no filters, hooks, LFS, submodule fetch, external object alternates or host clone hardlinks. Validate each source record and rehash copied content. Materialize new regular-file inodes inside a fresh disposable independent filesystem (private tmpfs candidate for bounded synthetic tests); never bind or snapshot the live tree or use live-tree lower layers. Handle internal symlinks as reviewed data; reject external/ambiguous links, special files, gitlinks and metadata control paths not explicitly supported. Do not interpret untrusted contents using unconfined extensible tools.
4. **B1 launch:** a trusted parent sets the private mount/PID/network view, reviewed runtime and policy RO, independently materialized project RW, minimal fake auth/inference channels, and explicit FD allowlist. A _trusted pre-exec shim_ imposes `no_new_privs`, verified Landlock ABI/rights, capability/IPC restrictions and FD closure **before any untrusted provider code, configurable loader, Git or plugin executes**. Abort closed if a required primitive is unavailable. No bind RW for host caches, package stores, toolchains, `.venv`, `node_modules`, home or live project; needed assets must be explicitly admitted and materialized or read-only trusted pinned runtime. Never grant Docker, user D-Bus, X11, ambient authority sockets or network as fallback.
5. **Freeze before export:** supervisor terminates and reaps the _whole_ B1-owned process tree (bounded cgroup/scope if safely available) and verifies no descendant remains writing; deny output when empty-tree or mount-writer assumptions cannot be established. Neither a direct-child list nor a timestamp/hash of a concurrently mutable tree is sufficient. No system-wide cgroup configuration or real-service modification is authorized for the synthetic phase.
6. **Restricted exporter:** a separately constrained process reads the frozen isolated filesystem **within a narrow mount/FD context**, never walks worker-controlled paths from the unrestricted host process. Do not follow symlinks, magic links or worker `.git`; open typed regular files with bounded `openat2` resolution, nonblocking/type checks and input limits, and represent safe symlinks as data rather than traversing them. Reject FIFO/socket/device, path ambiguity and oversize artifacts; export bounded typed records and verified file bytes into a second trusted/quarantine intake. This is a separate authority boundary (RV-4).
7. **Quarantine publisher:** never run Git with the worker's repository/config/hooks, nor load worker-provided extension rules. Revalidate typed paths, metadata, object types, digests and base OID. Reject `.git` paths or aliases, gitlinks, escapes and unsupported modes. Classify delayed-execution surfaces (e.g. `.github/`, `.vscode/`, `.claude/`, `.codex/`, `AGENTS.md`, `CLAUDE.md`, `.gitmodules`, `.gitattributes`, `.lfsconfig`, `.husky/`, `.envrc`, `package.json` scripts, executable bits and binary files) for elevated review; classification is **not** execution permission. Publish exact changes as a pending result in an independent quarantine object store/ref via compare-and-swap. Do not write the live working tree, source `.git` object store, current `HEAD` or source refs. A ref, CAS or fsck check gives integrity/atomic publication, **not authorization or merge safety** (RV-3/RV-5).
8. **Optional later U integration:** owner explicitly reviews quarantined content, provenance, base divergence and dangerous metadata, and invokes a separately governed U workflow. This design **does not implement or guarantee** safe unattended merge; no auto-apply even when the source seems exclusive. Ordinary editors may continue changing the live project; pending results retain their base identity and conflicts must be visible.

## 4. Filesystem/worker invariants (RV-2, RV-6, RV-7)

- A fresh private filesystem with independently created inodes must not share **any mutable data inode with any object outside its task instance**, including caches, U package stores, toolchains, original project or protected signer; bind-mounted RO trusted executable/library files are a distinct, explicitly reviewed runtime capability. Shared mutable inodes or unexpected extra mounts block launch.
- Hardlinks created entirely within the isolated task filesystem can be legitimate; no external inode alias can enter by staging. Paths, `st_nlink` or a new inode alone do **not** authorize content. Host-visible staging under the same UID would require extra isolation/review; private tmpfs is the **initial test candidate**, not an unrestricted scale decision.
- No untrusted executable runs before confinement. Pin minimum required Landlock ABI to actual rights used; observed host ABI 7 is a fact, not permission to claim ABI 9 pathname Unix socket protection. A trusted pre-exec shim validates restrictions and fails closed.
- Start from minimal grants: reviewed project regular file/dir creation, read/write, required executable and symlink features only; no gratuitous `MAKE_FIFO`, `MAKE_SOCK`, special devices or broad `REFER` without a demonstrated need. `EXECUTE` and links have specific test cases. A granted permission is not trusted behavior.
- Narrow reviewed PTY/stdio, no ambient FD or forbidden SCM_RIGHTS receiver; external Unix/IP socket, `/proc`, signals, ptrace and alternate IPC constrained/tested independently. Source & trusted policy and control-plane state are not automatically visible to B1.
- Restrict aggregate process, memory and storage usage with measurable per-task budgets, explicit abort and cleanup. In the first synthetic design, fix tmpfs byte/inode limits, timeouts, FD and worker count budgets **before tests** rather than inventing benchmark numbers.
- Every file boundary (admission, sandbox, export, quarantine and later U merge) has its own positive functionality and negative attacks. A denial by the mock/broker must not be reported as OS containment.

## 5. Native auth and network are explicit later gates (RV-8)

The fake-auth file-vs-directory matrix and narrow synthetic pipe/broker tests remain valuable, but do not prove native provider compatibility. Real subscription/OAuth/credential behavior, symlink/FIFO replacement on any shared auth directory, token leak potential and provider refresh require their own acceptance and owner authorization. Prefer a narrowly scoped credential-injecting proxy where the exact provider/version actually supports it; otherwise leave that provider outside B1 or escalate a genuine owner decision. Never silently copy real auth directories or share writable credential homes.

Real egress needs a separate audited protocol, allowlisted endpoints and post-resolution destination validation (loopback, link-local, LAN, CGNAT/tailnet, DNS rebinding, generic CONNECT and authorization header forwarding all considered). The FX-B1-C mock pipeline is not that proof. **Provider-stage release is BLOCKED until CG-15 and CG-16 pass and explicit owner permission is granted.**

## 6. Assumptions, open questions and stop conditions

- **No proof yet** that private tmpfs + shim + exporter + quarantine can be composed safely on the observed host. No host/runtime changes or benchmarks follow from this proposal.
- Trusted admission, exporter and publisher are critical: if an untrusted same-user U actor may modify them or their approval inputs, the B1-local claim must remain explicitly scoped and strong host-global approval must remain blocked.
- Import policy for Git submodules, symlinks, modes, LFS, extensions, local patches and deleted paths requires typed exact behavior and fail-closed errors. Avoid declaring "all Git works" from a tiny mock.
- Separate quarantine storage must reject hostile Git paths/config and not expose its own execution or admin credentials to the worker.
- The owner's preference for direct U work is preserved; the restriction applies only to tasks explicitly routed to B1.
- A new independent reviewer must evaluate the **plan and eventual implementation**. Codex authored the original experiment and candidate; the adversarial Claude reviewer contributed to this reconciled design, so neither is independent for those subsequent stages.
