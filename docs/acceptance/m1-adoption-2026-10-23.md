## What the installer does (read, then rehearsed in a temporary directory)

`install.sh install --keep-host` does not stop the host or any service. It puts the package beside the prefix,
renames the prefix to `<prefix>.previous` and the new one in its place (processes already running keep their
open files and their ID), rewrites the launcher, the icon, the `~/.local/bin` link, and, with `--f8-service`,
the protocol-2 unit file (no reload, no restart). Two things matter:

1. **Without `--f8-service` the launcher loses `--f8-authority`**: the rehearsal showed `Exec=…/wyss-console`
   alone, which would have switched the owner's protocol-2 interface off at the next start. The command that was
   used is the one that installed protocol 2 in the first place, with the same Codex path and `--allow-credential`
   (the flag only keeps the existing unit's argument; no credential is read or changed). The rewritten unit and launcher are
   byte-identical to the installed ones (checked by `diff` against the backup).
2. **`install.sh rollback` stops the host (`--wyss-host-stop`) and closes its terminals.** It is not the rollback
   of this adoption (below).

The desktop does not replace a running authority ("one that runs is never replaced"), so the first start of the new
desktop does not restart the protocol-1 authority or its Codex child.
