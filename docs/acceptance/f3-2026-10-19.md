# F3 acceptance: native launcher, registry and session profiles

Run 2026-10-19 on `saint-acer` (Plasma 6.7.5, Wayland session), against the installed Claude
Code 2.1.303 and Codex 0.159.0, in a nested display (KWin virtual + Xwayland) so the owner's
own session was not touched. The app was the release binary built from this branch, with its own
state directory (`XDG_STATE_HOME`) and the real `HOME`, so the agents used the owner's real
sign-in and settings. Nothing was answered in any agent's trust question, and the SHA-256 of
`~/.claude/settings.json` (`0c71027353dbf31e`) and `~/.codex/config.toml` (`bf11268d…`) was the
same before and after every step.

## Against the real agents (repeatable)

`cargo test -- --ignored real_agents --nocapture`: through the user's real shell (fish) each
agent started, reached its own first screen, was the process the terminal owns, had
`WYSS_NATIVE_SESSION_ID` and none of the markers of the Claude Code session the test ran in,
and stopped on Stop. Nothing is sent to either agent: no model is called by it.

`--settings` overlay, measured with the installed Claude Code in a temporary project: a
`SessionStart` hook wrote its marker without the overlay and did not with
`{"disableAllHooks": true}`; `skillOverrides` in the overlay disabled a skill. The same switch
covers hooks of the user's account by the provider's design; it was measured with a project
hook, not with the owner's own `rtk` hook.

## Found and fixed during the run

- A session started from a Console that itself runs inside Claude Code inherited that session's
  markers and messaging token (Claude Code warned "Transcript saving is off — inherited
  CLAUDE_CODE_CHILD_SESSION marker"). A closed list of per-session variables is now removed
  from the agent's environment (ADR 0035 §5).
- The user's fish puts `~/.local/bin` first, so a test PATH did not win: the tests use a shell
  without start-up files. This also confirms that the user's shell decides the `PATH`.
- Closing a native tab through the window and stopping from the overview both ended in a
  "failed" tab; a terminal closed by the desktop is now shown as closed.
- Overview rows overlapped their grid; the overview redrew twice a second and cost about 4 %
  of a core: usage is rounded and a read that would draw the same page changes nothing; one
  walk of `/proc` serves all sessions.
- The capability test forbids words such as stop, restart and profile for every permission; the
  native commands are a named, bounded exception, and the words that would mean a free command
  stay forbidden for them.

## One thing to know

While checking that the plain terminal still worked, one line (`echo regression ok`) was typed
into a Claude Code tab instead of the plain terminal: the tab strip had been re-ordered after a
restore. It went to a session of the test run only; no file was changed.

## Limits, stated

- A native session ends with the window (F9 is the phase that changes that); the Console says
  Lost, never exited.
- A profile cannot do for Codex what Codex has no per-session switch for (hooks, skills): it
  refuses to start and says why.
- The hooks-off overlay was measured with a project hook.
- Codex asked about a background server of another version in this environment (its own
  question, left at "Cancel" / "Run without daemon"); it is not something the Console decides.
