# F6: model catalogue, `model/rerouted` and native effort selection

2026-10-20, `saint-acer`, the owner's normal CachyOS/KDE account. ADR 0048. An increment of F6, not
completion of the whole phase or product.

## Delivered

A **Models** view with four lists kept apart (offered / configured / selected / reported in use),
each with where it comes from; the managed Codex catalogue with what the runtime's own listing
says per model (default mark, supported efforts, replacement marking, completeness), with
provenance, freshness and an explicit "listing is not entitlement"; `model/rerouted` accepted for
exactly the running turn and exactly the schema; a native **reasoning effort** in profiles, passed
the way each agent documents; Claude Code's own `/model` hint in the workspace (none for Codex,
whose command is not verified). **No managed model choice** (SG-12 and ADR 0014/0015 untouched).

## Independent review (before this is called a protection)

A cold external review (Codex, via `codex-gsd-check`, given the contract and threat model and none
of the builder's reasoning) of the first version returned one **MEDIUM**: `bounded_word` accepted
spaces, links and non-ASCII in the replacement and retirement fields, which reach the window. It
found nothing in the classifier, the turn controller or the observation. Fixed (identifiers are
printable ASCII without space, a retirement is a date or nothing, each word of a listing is judged
alone), with tests that fail on the earlier code (spaces, a link with prose, accents, a date in
words); the TypeScript parser is as strict.

## Real window (the owner's own HOME, wallet and running authority and host)

An unpinned release build (it manages no authority, so the running authority PID 1167285 and the
real host PID 1188641 were not touched), shown in an isolated display. The owner's GUI PID 1310334
was never touched; mine was ended by exact PID and its display torn down.

- **Models** opened against the **running older authority**: the 7 models the managed Codex runtime
  listed (version 0.159.0, Inference), "Listed once by the managed Codex runtime… Read from the
  authority at …", "A model being listed does not mean your account can use it", "Whether this list
  is complete is not reported by this authority version", and "Efforts: not reported by this
  authority version" for each: the old-authority decode path, in the real system. Configured, from
  the real files: Claude Code `effortLevel: high`, `model: sonnet`; Codex `model: gpt-6.1-sol`,
  `model_reasoning_effort: medium`; OpenCode `model: google/gemini-3.5-flash`. Reported in use: "No
  managed session is attached", with the note that native agents do not report one.
- **Profile**: a profile named "Acceptance F6" with model `sonnet` and no effort was created through
  the **older host** that is kept running across an upgrade, appeared under "Selected by a profile",
  showed "Model: sonnet." in the launcher's preview, and was deleted again. With an **effort**, the
  same older host refused the request. That defect (found only here) is fixed: the host now says
  which features it has, the window refuses to send what an older host cannot keep, and says so in
  words ("The terminal host that is running is older than this window and cannot keep a reasoning
  effort. Close your terminals and restart the app… or leave the effort empty."). A body without an
  effort goes to an older host byte for byte as before. The scroll of the Models view, a double
  period and a noisy OpenCode provider list were also found and fixed here.

## Provider evidence (no model prompt, no paid credential)

- **Claude Code 2.1.304**: `claude --effort high --model sonnet -p ""` is accepted at parse time and
  stops at "Input must be provided"; `--effort bogus` prints "Unknown --effort value 'bogus' …
  Valid values: low, medium, high, xhigh, max." So the closed set the profile uses is the provider's.
- **Codex 0.159.0** (`app-server` `config/read`, read only): without an override the effective
  `model_reasoning_effort` is the file's `medium`; with `-c model_reasoning_effort="high"` it is
  `high`, and with `"minimal"` it is `minimal`, while the file is unchanged. That is the mechanism the
  profile uses, shown to take effect on the provider's own configuration. Whether the provider then
  runs a turn on that effort is not claimed.

## Not proven, and why

- The **new authority behaviour** (offers, completeness, replacement marking, `model/rerouted`) is
  proven by unit and contract tests only. The authority running on this computer is older ("update
  pending"), and replacing it would interrupt its managed sessions, which this work does not do.
  It is applied when the package is installed with the owner's authority upgrade.
- **Codex has never been observed sending `model/rerouted`** to this client (OQ-50). The classifier
  and controller are written to the schema and tested with synthetic notices, not a real one.
- An effort saved in a profile and run through the **new** host was not exercised in the real window
  (the running host is older); its path is covered by the host and profile tests.
- Provider consumption: not demonstrated beyond the above. A managed session's observed model was not
  shown (none attached).
