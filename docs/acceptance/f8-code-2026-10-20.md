# F8 inactive implementation: protocol, offline migration and registry

Continued clean private main `55fa2ca` on Santiago's real CachyOS account. No installation,
authority migration, restart, provider launch, inference, configuration write or gateway exposure.
ADR 0051 remains Proposed. This record supersedes “design only/no code” for the slices below,
not the remaining production acceptance requirements.

## Working code and precise boundary

- `src-tauri/src/f8/protocol.rs`: request parse/encode for the closed 29-method vocabulary, typed
  preserved runtime target/fence, existing operation validators, strict envelopes/version, duplicate
  JSON rejection, frame limits, canonical UUIDs, u63 bounds and explicit handshake correlation.
  Extra model/effort/argv/env/PID fields still refuse; original accepted typed turn input and
  local-tools workspace/profile restrictions are inherited unchanged.
- Response parse/encode preserves typed runtime/history/attachment projections, separates durable
  references from live version observations, checks authority/instance/session consistency and
  closed errors/budget diagnostics. Runtime control correlation checks generation, revision and
  desired state; catalogue cursors cannot cross an instance or exceed index 50. Hello/status typed
  projections retain protocol 2/schema 8, not the baseline versions used internally for validation.
  **Partial codec boundary:** vocabulary-2 audit results return `unsupported`; response method/result
  correlation currently supports hello/status/runtime methods and returns `unsupported` for other
  successful methods. This cannot be used as a complete protocol-2 client/server yet.
- `src-tauri/src/f8/migration.rs`: `prepare` reads a consistent caller-owned source transaction,
  validates exact supported V0–V7 objects and FK/integrity, copies into memory, applies the unchanged
  supported migration path to V7, validates canonical records/audit/receipts, then executes candidate
  V8 SQL in an IMMEDIATE transaction with validation before commit. Source is never written.
  No path opener, installed-database selector or publication method exists. The returned private
  image exposes validation and metadata only, no mutable Connection.
- `validate_migrated` checks exact V8 objects, integrity/FKs, metadata and unchanged canonical
  legacy history through a V7 projection. It **refuses every nonempty new V8 runtime/sidecar table**.
  This is an immediate-migration validator, not validation of a V8 store that has accepted new work.
  Unknown schema, extra objects, partial migration and temp/attached shadowing refuse. Preparation
  copies O(database size) into memory; no bounded live migration or DB/WAL restore claim.
- `src-tauri/src/f8/registry.rs`: identity-only registry retains one active slot across reserved,
  initializing, ready and stopping until caller-reported owned reap. Validates authority, session,
  instance and generation; rejects stale/reused identities. The bounded in-memory replay cache uses
  a SHA-256 fingerprint including targeting and preserves receipts across transport request IDs.
  It is not the durable journal. Registry observation cannot grant leases, accept approvals, spawn,
  signal, dispatch or attest OS liveness. Durable allocation/restart monotonicity and proof of reap
  remain required at future integration; no registry observation is an execution capability.

The active server/client/store-opening paths still use protocol 1/schema 7 and the existing capacity
of one. The only shared implementation addition is a read-only, memory-image-only wrapper around
existing canonical Store verification; active opening/verification behavior is unchanged.
No dependency, crypto protocol, network transport or listener was added.

## Adversarial evidence and review

Seventeen new tests run against implementation code, separately from the ten existing reference tests:

- Real request/response roundtrips, old protocol rejection, malformed/duplicate/oversized JSON,
  noncanonical UUIDs, unknown/generic execution fields and numeric bounds.
- Crossed LeaseGrant session/fence, crossed authority, stale generation/revision/state, crossed
  catalogue cursor and identity, stopping capacity, stale/reused instances and actual replay-cache
  lookup/conflict without a provider effect.
- Canonical seeded V1–V7 stores (sessions/receipts, runtime history from V2 and revoked leases from V3) and empty V0 migrate to validated V8 images. Every candidate SQL
  statement boundary and the final validation boundary is fault-injected for **every version**;
  tests assert the intended hook was reached and original schema/rows/user_version stay exact.
- Invalid receipts, unlogged sessions, corrupt records/schema, future/partial schema, active-lease
  refusal and unknown new V8 work refusal. This does not substitute for future V8 event replay,
  durable replay resolution, WAL backup/restore or process/scheduler adversarial tests.

Independent code review found and corrected five codec defects: missing inline `session_id` versus
fence comparison, missing canonical `session_id`, incomplete response authority correlation,
unchecked runtime-control generation/revision/state, and crossed model cursor. It also prompted
removal of the public Connection accessor. Real negative tests cover these corrections. Follow-up
review found no remaining blockers **within this offline/observational/partial-codec boundary**;
it did not approve production integration, provider safety or owner-dependent contract changes.
Reviewers executed the two then-existing response tests; the final implementation suite passed all
17 after fixes. Local logs are in `.artifacts/acceptance/f8-code/`.
