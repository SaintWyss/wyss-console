# F8 inactive implementation: protocol, offline migration and registry

Continued clean private main `55fa2ca` on Santiago's real CachyOS account. No installation,
authority migration, restart, provider launch, inference, configuration write or gateway exposure.
ADR 0051 remains Proposed. This record supersedes “design only/no code” for the slices below,
not the remaining production acceptance requirements.

## Working code and precise boundary

- `src-tauri/src/f8/protocol.rs`: request parse/encode for the closed 29-method vocabulary, typed
  preserved runtime target/fence, existing operation validators, strict envelopes/version, duplicate
  JSON rejection, frame limits, canonical UUIDs, u63 bounds and explicit handshake correlation.
  Extra model/effort/argv/env/PID fields still refuse; original accepted typed turn input and
  local-tools workspace/profile restrictions are inherited unchanged.
- Response parse/encode preserves typed runtime/history/attachment projections, separates durable
  references from live version observations, checks authority/instance/session consistency and
  closed errors/budget diagnostics. Runtime control correlation checks generation, revision and
  desired state; catalogue cursors cannot cross an instance or exceed index 50. Hello/status typed
  projections retain protocol 2/schema 8, not the baseline versions used internally for validation.
  **Partial codec boundary:** vocabulary-2 audit results return `unsupported`; response method/result
  correlation covers all non-audit methods, with independently accepted canonical-workspace
  context required for binding creation. This cannot be used as a complete protocol-2 client/server yet.
- `src-tauri/src/f8/migration.rs`: `prepare` reads a consistent caller-owned source transaction,
  validates exact supported V0–V7 objects and FK/integrity, copies into memory, applies the unchanged
  supported migration path to V7, validates canonical records/audit/receipts, then executes candidate
  V8 SQL in an IMMEDIATE transaction with validation before commit. Source is never written.
  No path opener, installed-database selector or publication method exists. The returned private
  image exposes validation and metadata only, no mutable Connection.
- `validate_migrated` checks exact V8 objects, integrity/FKs, metadata and unchanged canonical
  legacy history through a V7 projection. It **refuses every nonempty new V8 runtime/sidecar table**.
  This is an immediate-migration validator, not validation of a V8 store that has accepted new work.
  Unknown schema, extra objects, partial migration and temp/attached shadowing refuse. Preparation
  copies O(database size) into memory; no bounded live migration or DB/WAL restore claim.
- `src-tauri/src/f8/registry.rs`: identity-only registry retains one active slot across reserved,
  initializing, ready and stopping until caller-reported owned reap. Validates authority, session,
  instance and generation; rejects stale/reused identities. The bounded in-memory replay cache uses
  a SHA-256 fingerprint including targeting and preserves receipts across transport request IDs.
  It is not the durable journal. Registry observation cannot grant leases, accept approvals, spawn,
  signal, dispatch or attest OS liveness. Durable allocation/restart monotonicity and proof of reap
  remain required at future integration; no registry observation is an execution capability.

The active server/client/store-opening paths still use protocol 1/schema 7 and the existing capacity
of one. The only shared implementation addition is a read-only, memory-image-only wrapper around
existing canonical Store verification; active opening/verification behavior is unchanged.
No dependency, crypto protocol, network transport or listener was added.

  statement boundary and the final validation boundary is fault-injected for **every version**;
  tests assert the intended hook was reached and original schema/rows/user_version stay exact.

## Continued implementation: non-audit result correlation

After committing/pushing `e00903c`, continued with working code rather than another design cycle.
Response correlation now has an exhaustive allowlist of result kinds for all non-audit operations,
plus request/result record-ID checks for sessions, leases, bindings, turns, stream events and
approvals. Lease grants/renewals compare exact durations, scopes/state/revisions as appropriate;
lists check bound/order/unique session IDs and cursor attribution. Returned records remain
informational: correlation cannot replace store ownership joins, expiry/lease/gate checks or
execution attestations before dispatch.

Binding-create correlation requires the independently accepted canonical workspace through
`correlate_binding_create`; generic correlation refuses that successful result without context.
It never resolves paths, especially not when validating a replay whose original workspace may no
longer exist. A closed-session no-op keeps revision 2, matching the existing authority contract.
Both behaviors received positive regression tests, alongside crossed-ID, wrong result-kind,
wrong state/revision/decision, fractional-TTL and wrong cursor negatives.

Focused independent review found the closed-session no-op and textual/canonical workspace
mismatches; both corrected. Exact duration and active-lease checks are explicit. The final focused
suite passes **23/23** implementation tests (the original 17 plus six correlation tests).
Vocabulary-2 audit response validation, V8 new-work canonical replay/validators, durable runtime
allocation/replay, scheduler, owned workers and integration remain pending. No installed update.

Turn-stream correlation additionally refuses ordinary events at/before the requested cursor and
requires `next_sequence` to equal the last returned event. The special synthetic `StreamGap`
sequence is preserved. Positives use the real `Streams::page` implementation for missing and evicted
rings; stale ordinary events and wrong next cursors refuse. The helper exists only under `cfg(test)`.
Independent follow-up found no blockers in this non-audit increment after those corrections. The
extra active-lease state check is defense in depth: the baseline parser already rejected non-active
`active_lease` values, so this was not a prior parser vulnerability.

Final regression: `npm run check:rust` passed with 659 library tests before adding the last stream
fixture, 361 bin tests, one authority boundary and ten reference tests; final focused F8 suite
**23/23** and final all-target Clippy passed. Frontend remained the previously verified 835/835,
harness 15/15 and build; no frontend implementation changed in this increment.

## Continued implementation 2: audit vocabulary 2, post-migration V8 validator, durable allocator

All inactive; no installed store, provider, process, socket or configuration was touched.

- `f8/audit.rs`: strict vocabulary-2 payloads (runtime events, turn/approval `generation`), unchanged
  vocabulary-1 validation on original bytes, canonical IDs and the 2 KiB bound on the wire, closed
  vocabularies/budget keys, `check_page` for audit responses and `AuditReplay` (sole-writer authority
  succession so a retired authority cannot write again, disjoint identity domains, launch attribution,
  ready/exit once, owner-only progress, recovery-class events only for non-live launches, SQL-matching
  transition tables, per-session pending/active uniqueness, 128/4096 limits, `unresolved_for` listing
  work stranded on a predecessor's launch). A refusal poisons the replay.
- `f8/v8.rs`: `validate_v8` accepts legitimate new work and proves it: exact schema, baseline
  canonical verification through a flag-gated schema-8 mode of the existing verifier (unreachable for
  schema 7), full audit replay, runtime/launch/sidecar/receipt joins, unassigned history must be
  finished, baseline receipts need a baseline event, V8 receipts must match the replayed mutation
  exactly. `commit_validated` rolls back everything on any refusal. Restart is exercised by
  `VACUUM INTO` + reopen. This is an in-memory/copy discipline; it proves nothing about the installed
  database, WAL restore or O(database) cost on real data.
- `f8/allocator.rs`: atomic reservation (runtime row, launch, event, receipt in one IMMEDIATE
  transaction), replay before capacity, conflict on changed intent, retention only of a live launch
  owned by the same authority, failed attempts consume generations, overflow/capacity refuse before any
  write, stop fences the observed launch (null is not a wildcard), once-only owner-only ready/exit,
  predecessor launches reported unowned, registry history priming. Every write step fault-injected.
- Independent review (separate agent) of the first commit found 10 issues, 8 of them real security or
  correctness gaps (baseline work after V8 start, non-owner/successor progress, compatibility word,
  transition tables, forged baseline receipts, receipt/event coupling, identity domains, wire
  canonicalisation); each has a regression test. **Still NOT_PROVEN / accepted limits:** there is no
  migration-boundary marker in the frozen SQL, so before the first V8 event a forged baseline-shaped
  record cannot be distinguished from real history; a successor authority is not attested by the
  stream, only its sole-writer ordering is enforced (a forged successor is detected when the real
  authority next writes); `events_for` scans the log (fine offline, needs an index before any live use).
- Validation: focused F8 suite 59/59; `npm run rust:test` 696 lib + 361 bin + 1 + 10 passing; fmt and
  all-target Clippy with warnings denied clean. No blanket `cargo test`.

## Continued implementation 3: owned processes, budgets, scheduler, staging, engine (inactive)

- `f8/ownership.rs`: pidfd-only signalling of children this code spawned (no name/PID/group
  selection anywhere, including the tests), bounded non-blocking EOF→TERM→KILL→reap, close-on-exec of
  every inherited descriptor, descendants reported but never signalled. Requirement: `spawn` must run on
  a thread that lives as long as the authority (PDEATHSIG is per thread).
- `f8/budget.rs`, `f8/scheduler.rs`, `f8/staging.rs`, `f8/engine.rs`: contract-classified budgets
  (RSS soft only; some ceilings NOT_PROVEN), reserved-control fair scheduler with fault isolation,
  exclusive private launch staging (cleanup always removes the pinned directory), and an engine whose
  fence/lease/attachment/turn checks are repeated immediately before every write, approvals answered
  only through closed decisions after revalidation, unexpected exits/timeouts/wall clock detected by `poll`.
- Tests: F8-01..F8-18 run against this code (F8-16 simulates audit-store failure by a failing insert,
  not a real full disk; approval-outcome durability is NOT_RUN because no V8 turn/approval writer exists).

- Codex shared state: see `docs/research/f8-codex-shared-state-2026-10-20.md`; capacity stays 1.

## Continued implementation 4: trust boundary, attestation, writers, process worker, facade, containment

All inactive; no installed authority, database, GUI, host, terminal or configuration was touched; no
authenticated Codex was launched; capacity stays 1.

- **Migration trust boundary** (failing tests first: forged baseline history after migration and rewritten
  pre-migration history were accepted). The frozen SQL gains `migration_boundary` (immutable); the
  migration records the V7 head and a SHA-256 over every V7 event. Replay refuses version-2 payloads
  before it, baseline runtime/turn/approval events after it, and detects rewritten history.
- **Successor attestation:** `authority.instance.started` (null session) names the predecessor; after the
  boundary every authority instance must announce itself before its first event. Remaining limit: the
  stream cannot prove a successor is _real_, only that the chain is consistent and a retired authority
  cannot write again.
- **Durable writers** (`f8/writers.rs`): turn admit/transition/cancel, approval open/decide/confirm/settle/
  expire, lease grant/renew/revoke/expire with same-transaction loss of admitted work, and recovery of
  work stranded on a launch the recovering authority does not own. Sidecars, v2 events, receipts and
  replay are validated end to end by `validate_v8` (the baseline verifier included). F8-16's
  approval-outcome path is covered: a failing audit append leaves the approval pending and entitles no
  provider answer; an unrecordable confirmation keeps the accepted effect unconfirmed.
- **Process worker** (`f8/process_worker.rs`): bounded non-blocking newline-framed pipes around an owned
  child, back pressure instead of waiting, bounded inbound slices, oversized-line failure, stderr
  drained and discarded. Tested with shell fixtures only.
- **Authority facade** (`f8/authority.rs`): strict protocol 2 / schema 8 for hello, status, runtime
  start/stop/status, lease grant/renew/revoke/get/active, turn start/cancel, approval respond and audit
  read, with fences, replay, cancellation and scheduler pumping. Prepare/close, bindings, model list,
  turn/approval reads, gate query remain `unsupported` (need schema-8 ports).
- **Descendant containment:** the existing production bwrap launch has `--die-with-parent` but no
  `--unshare-pid`, so grandchildren are not contained there (reported, unchanged). F8 accepts full
  containment only for the root-owned launcher with `--unshare-pid --die-with-parent` before `--`;
  a real-bwrap test shows every descendant ends when the owned launcher is stopped. A tool-capable
  profile is refused (nothing reserved) unless the spawner provides it, and the handshake re-checks the
  observed namespace.
- Validation: `npm run rust:test` 777 lib + 361 bin + 1 + 10; fmt and Clippy `-D warnings` clean.
- **Independent review of this last delta: NOT_RUN** (requested after reporting). Treat items 1-5 of the
  task as tested but not independently reviewed.
