## Rollback and adoption

Adoption is the owner's explicit act, in this order, each step reversible:

1. Install a build that contains this branch with the usual `install.sh --keep-host` (the package
   command is not changed by this delivery). The workspace is **off**.
2. Settings → Projects and workspaces → **Turn on…** and confirm in the native window. The
   Projects entry appears.
3. Projects → **Preview the import** (reads, changes nothing) → **Import**. The legacy registry and
   layout are copied byte for byte into `…/projects/v1/migration-<id>/` with a hash manifest, then
   the store is published. The older windows keep their own files and keep working.
4. Later changes in the older windows are offered as a new, incremental preview.

Going back: **What going back needs** reports what the store holds and refuses while a launch of
unknown outcome is unaccounted for; then **Turn off…** in Settings. No session is stopped, no
legacy file is restored over a live writer, the store, its tombstones and the snapshot are kept for
a later return, and the older windows may recreate missing shells by their own behaviour (say so
before relying on it). An unusable store is shown read-only with its exact bytes untouched; it is
never replaced by an empty one, and "Start empty" is only offered when there is no store at all.

## Release and adoption conditions (not done)

- The owner turns the gate on in an installation of their choice and runs the import against their
  real registry and layout. Until then no real-state migration, no real Native agent through the
  Projects view and no real Managed session through it has been exercised.
- GUI performance budgets are agreed from measurements on that installation (input-to-render,
  project switch p50/p95/p99, restore, RSS/PSS, CPU and wakeups, with three independent runs).
- A foreign ACL on a project root is not detected (owner only); decide whether that matters.
- A Managed launch only prepares a session; running one still happens in the Managed screens.
- ADR0053 (Claude Managed) and concurrency above one remain out of M1.
