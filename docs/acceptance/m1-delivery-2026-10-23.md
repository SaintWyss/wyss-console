### The real desktop

**Procedure.** The release build of this branch (`src-tauri/target/release/wyss-console`) ran in a virtual
KWin compositor and Xwayland made for each run (a session bus of its own for each), with its own home,
state and runtime directories, its own disposable terminal host (`--wyss-host`, real `fish` shells), and
projects, workspaces and shells made by the commands the window sends
(`projects::tests::perf_world`). The nine runs below were made on `9501c4b` (SHA-256
`fdb034250f7cd859…`); the independent review then found nine things, whose fixes changed product code
(`30756bc`, SHA-256 `7814ba9c4b00eb19…`), so **one more run of each shape was made on the final build**
(next to the figures, `evidence/…/postreview/`). Three shapes, three runs each, every run from a clean
directory: **a** 1 terminal, 2 workspaces; **b** 16 terminals in 16 projects and 32 workspaces; **c**
16 terminals in one workspace (4×4). Per run: three cold starts of the application over the same
store and host (restore: click on a project to its settled picture), 40 random project switches
(click to the first frame equal to the target's settled picture), 40 screen clears and 40 single
characters typed in the pane that holds input (key to the first frame that shows the change), and
60 seconds of idle sampling each of: the older Console view alone, the Projects view shown, and
the Projects view hidden. The owned tree is the application, its WebKit processes, the host and the
shells; memory is read from `/proc` (RSS and PSS), processor time from `stat`, wake-ups are voluntary
context switches counted thread by thread between neighbouring samples. The raw samples of all
nine runs (every latency, every one-second sample of every process) are in
[evidence/m1-perf-2026-10-23/](evidence/m1-perf-2026-10-23/) with the report that aggregates them
(`report.md`, `benchmarks/m1_gui_report.py`); nothing was dropped, and one failed attempt is kept
as `superseded/` (the first instrument summed per-thread counters, which can go backwards when a
thread ends; its latency figures agree with the nine runs).

**Conditions.** Intel Core i5-10300H (4 cores, 8 threads), 15 GB, Linux 6.18.55 (CachyOS LTS), the
owner's own desktop session and services running beside the runs (load average 0.25–0.82 at the
start of each run, 8.3–8.8 GB available); release build; no window manager (a click inside the
terminal gives the page the keyboard, as a person's first click would). **Limits.** Frames are
grabbed at 60 a second, so a figure is quantised to about 17 ms and carries the grabber's own
latency, which was not subtracted; "input to render" includes the shell's own redraw (`fish`);
the older Console view, which attaches to the same terminals, is part of the application in every
run, and it is by far the largest idle cost with 16 terminals; no real Claude or Codex agent and no
Managed authority were running; memory differs by up to about 60 MiB between the states in the same
run because the WebKit process drifts over a run, so no state is claimed to cost more memory than
another; three runs per shape bound run-to-run spread, they do not give a confidence interval.

## Rollback and adoption

Adoption is the owner's explicit act, in this order, each step reversible:

1. Install a build that contains this branch with the usual `install.sh --keep-host` (the package
   command is not changed by this delivery). The workspace is **off**.
2. Settings → Projects and workspaces → **Turn on…** and confirm in the native window. The
   Projects entry appears.
3. Projects → **Preview the import** (reads, changes nothing) → **Import**. The older registry and
   layout are copied byte for byte into `…/projects/v1/migration-<id>/` with a hash manifest, then
   the store is published. The older windows keep their own files and keep working. A registered
   folder another account can write is not imported unless the account is named in
   `~/.local/state/wyss-console/configuration/trusted-writers` (the file the configuration engine
   already reads; it names `agent` today).
4. Later changes in the older windows are offered as a new, incremental preview.
