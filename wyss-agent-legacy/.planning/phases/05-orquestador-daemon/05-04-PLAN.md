<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI cliente → daemon (Unix socket) | JSON-RPC desde el shell del owner; el socket 0600 limita a procesos del owner |
| Plan (de Hermes/cliente) → engine | Todo Plan cruza engine.evaluate antes de cualquier acción — única compuerta |
| owner → wyss confirm | Resolver una propuesta; debe ser durable y no ejecutar stale |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11 | Elevation of Privilege | Plan nivel D ejecutado por el daemon | mitigate | dispatch: REJECT or risk>=D → audit+refuse, ningún path ejecuta (POL-03 inviolable). Testeado (test_dispatch_d_rejects_and_audits). |
| T-05-12 | Spoofing | otro usuario conecta al Unix socket | mitigate | `os.chmod(socket_path, 0o600)` inmediatamente tras bind; solo el owner accede (Security Domain RESEARCH). |
| T-05-13 | Elevation of Privilege | acción D enviada por JSON-RPC directo (bypass de Hermes) | mitigate | engine.evaluate es la ÚNICA compuerta y el daemon la llama siempre, venga el Plan de Hermes o de un cliente directo. |
| T-05-14 | Denial of Service | confirm bloquea el event loop esperando ejecución | mitigate | D-57: confirm solo encola + responde execution_id; ejecución real es Fase 6 (Pitfall 7). |
| T-05-15 | Tampering | JSON-RPC con tipos corruptos (risk_level int desde JSON) | mitigate | dispatcher fail-closed: outcome/risk no-enum → REJECT (patrón agent.py isinstance). |
| T-05-16 | Repudiation | acción sin auditar | mitigate | cada branch del dispatcher loguea POLICY_DECISION/CONFIRMATION_REQUESTED; wyss audit lo expone. |

Block on HIGH: T-05-11 y T-05-13 (D ejecutado / bypass del engine) son HIGH — el daemon debe pasar SIEMPRE por engine.evaluate y D nunca ejecutar.
</threat_model>
