<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
    Canal de intake externo completo: RPC `intake.propose` con floor B (13-01) + endpoint
    `POST /api/intake` con bearer dedicado, rate limit propio y exención de cookie acotada (13-02).
    Config `[intake]` opt-in. El intake nunca ejecuta directo; todo cae a la bandeja como ≥B.
  </what-built>
  <how-to-verify>
    Preparación:
    1. Habilitar intake en config.toml: sección `[intake]` con `enabled = true` y
       `max_per_minute = 5` (bajo, para probar el 429 rápido).
    2. Levantar el daemon: `wyss start` (en una terminal).
    3. Levantar el bridge en LAN: `wyss web --lan` (en otra terminal). Anotar el host:puerto
       (p.ej. https://192.168.x.x:7777) y aceptar el cert self-signed si aplica (`-k` en curl).
    4. Leer el bearer: `cat data/intake_token` (ese es el valor para el header Authorization).

    Verificación (imitando a n8n con curl):
    a. BEARER VÁLIDO → propuesta en bandeja:
       `curl -k -X POST https://<host>:<port>/api/intake -H "Authorization: Bearer <TOKEN>"
        -H "Content-Type: application/json" -d '{"instruction":"recordá comprar café mañana"}'`
       Esperado: 200/201 con outcome "pending" y un pending_id. Luego `wyss pending` (o GET
       /api/pending con la cookie del navegador) debe MOSTRAR esa propuesta como nivel B o C.
    b. SIN BEARER → 401:
       `curl -k -X POST https://<host>:<port>/api/intake -H "Content-Type: application/json"
        -d '{"instruction":"x"}'`
       Esperado: HTTP 401 con {error, accion}. Revisar el log del proceso `wyss web`: debe
       registrar el 401 SIN mostrar ningún valor de token.
    c. BEARER INVÁLIDO → 401:
       repetir (a) con `Authorization: Bearer no-es-el-token`. Esperado: 401.
    d. FLOOD → 429:
       correr (a) 6+ veces seguidas en < 1 minuto (max_per_minute=5). A partir de la 6ª:
       HTTP 429 con {error, accion}.
    e. NO AUTO-EJECUCIÓN: confirmar que ninguna de las propuestas de (a) se ejecutó sola —
       siguen en `wyss pending` esperando el sello del owner (o expiran por TTL sin ejecutar).
    f. (OPCIONAL) Workflow n8n real: crear un HTTP Request node en n8n apuntando a
       `POST https://<host>:<port>/api/intake` con el header Authorization: Bearer <TOKEN> y
       body `{"instruction":"..."}`; ejecutar el workflow (idealmente el trigger programado, no
       solo "Execute Workflow" manual) y confirmar que la propuesta aparece en la bandeja.

    Al terminar, si el owner quiere el intake apagado por default: volver `[intake].enabled = false`
    y confirmar que `POST /api/intake` devuelve 404.
  </how-to-verify>
  <resume-signal>Escribí "approved" si a-e (y opcionalmente f) pasan, o describí qué falló.</resume-signal>
</task>
