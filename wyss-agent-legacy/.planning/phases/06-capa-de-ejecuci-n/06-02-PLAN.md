<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| journal → filesystem | restore() writes files back to recorded origins; a tampered inverse_op could redirect a write |
| executor → journal | journal records BEFORE mutation; a missing record means an irreversible action |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-UNDO-1 | Tampering | restore() writing outside intended target | mitigate | restore() moves only to the `origin` recorded at record-time; origins are paths the action already resolved through the second wall (plan 04) before record was called |
| T-06-UNDO-2 | Tampering | journal/trash corruption losing reversibility | mitigate | WAL fail-fast constructor (AuditIntegrityError) refuses to operate on a non-durable FS; overwrite backups stored as real files in data/undo_backups, not BLOBs |
| T-06-UNDO-3 | Repudiation | irreversible mutation with no journal entry | mitigate | record() is called BEFORE any I/O (plan 04 ordering); executor rollback (plan 05) depends on this invariant |
</threat_model>
