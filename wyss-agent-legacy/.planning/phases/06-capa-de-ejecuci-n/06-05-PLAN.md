<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon dispatcher → executor | a confirmed Plan crosses into real execution; each step's adapter enforces its own second wall |
| executor → journal | rollback correctness depends on applied entries being restored in reverse |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-undo-corruption | Tampering | ABORT rollback path | mitigate | journal.restore applied in REVERSE order over entries the FS adapter recorded before each mutation; partial-failure leaves the FS in a journal-reversible state |
| T-verify-bypass | Spoofing | per-step verify gate | mitigate | a step with verify.passed=False is treated as a failure and triggers on_error — success is never reported on an unverified step |
| T-06-EXEC-1 | Repudiation | ESCALATE without trace | mitigate | ESCALATE logs a TASK_FAILED/escalate AuditEvent with the step index before propagating; failures are never silent (ORCH-07 doctrine) |
| T-06-EXEC-2 | Denial of Service | RETRY hammering a failing step | mitigate | RetryParams.max_attempts caps retries; exponential backoff capped at backoff_max_s |
</threat_model>
