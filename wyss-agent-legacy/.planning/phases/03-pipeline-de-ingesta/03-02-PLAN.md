- mkdir parents; os.open(db_path, O_CREAT, 0o600); os.close(fd); sqlite3.connect

- apply_index_schema(conn); return conn

Patrón PRAGMAS + DDL idempotente (src/gateway/traces_schema.py):
- PRAGMAS = ("PRAGMA journal_mode=WAL", "PRAGMA synchronous=FULL", "PRAGMA busy_timeout=5000")
- apply_schema(conn): execute cada CREATE TABLE/INDEX (todo IF NOT EXISTS) + commit

Schema file_state (RESEARCH Pattern 2 + PATTERNS): PRIMARY KEY (path, kb_id) — un mismo archivo
puede estar en varias BC (Open Question 3). Columnas: path, kb_id, size, mtime, sha256 (NULL hasta
que cambió), status DEFAULT 'pending', attempts DEFAULT 0, error, indexed_at, updated_at.
Índices: idx_file_state_status(status), idx_file_state_kb(kb_id).
La tabla `chunks` (contenido canónico para FTS5 external content) también vive en index.db — su DDL
se define acá pero la usa el FTS5 adapter (plan 05). Schema chunks: chunk_id PRIMARY KEY, kb_id,
source_path, position, text.

needs_reindex (RESEARCH Pattern 2): None→True (nuevo); status=embedded y size+mtime iguales→False
(fast path, NO calcula hash); embedded con size/mtime cambiado→calcula sha256 y compara; cualquier
otro status (pending/extracted/failed)→True.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem (NTFS) → index.db | El owner puede mover data/ a NTFS donde WAL degrada → corrupción de estado |
| filesystem → StateStore | Paths de archivos no confiables se persisten como datos (no se ejecutan) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | index.db sobre NTFS dirty-bit/fuseblk | mitigate | Smoke test WAL fail-fast en open_index_db: journal_mode != wal → IndexIntegrityError (Pitfall 3, espejo de audit.db/traces.db) |
| T-03-05 | Information Disclosure | error guardado en file_state.error | mitigate | mark_failed guarda solo el tipo/mensaje de error truncado, nunca el contenido del archivo (doctrina D-20) |
| T-03-06 | Tampering | SQL de file_state | mitigate | INSERT/UPDATE solo con parámetros `?`, nunca interpolación de string (espejo de traces.py) |
| T-03-07 | Information Disclosure | permisos de index.db | accept | index.db lleva paths+hashes, no contenido sensible; aun así chmod 0600 best-effort (espejo de gateway/db.py) reduce exposición |
</threat_model>
