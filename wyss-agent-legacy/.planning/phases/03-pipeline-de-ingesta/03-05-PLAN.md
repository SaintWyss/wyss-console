Protocols (src/core/ports/knowledge.py):
  Chunker.chunk(self, content: ExtractedContent) -> Sequence[Chunk]
  FullTextIndex.upsert(self, entries: Sequence[IndexEntry]) -> None
  FullTextIndex.search(self, query: str, kb_ids: frozenset[str], limit: int) -> Sequence[Hit]
  VectorIndex.upsert(self, entries: Sequence[tuple[IndexEntry, Vector]]) -> None
  VectorIndex.search(self, vector: Vector, kb_ids: frozenset[str], limit: int) -> Sequence[Hit]

Dominio: Chunk(chunk_id, text, source_path, position); IndexEntry(entry_id, kb_id, chunk);
Hit(entry_id, score, snippet, source_path); ExtractedContent(source, text, metadata);
type Vector = tuple[float, ...]. De plan 01: IngestSettings (chunk_size_tokens=512,
chunk_overlap_tokens=51 por defecto).

FTS5 external content (RESEARCH Pattern 3, [CITED sqlite.org/fts5.html]): la tabla `chunks` ya
existe en index.db (DDL de plan 02 index_schema). Acá se agrega la VIRTUAL TABLE chunks_fts
(content=chunks, content_rowid=rowid, tokenize='unicode61') + triggers chunks_ai/ad/au. El FTS5Index
recibe la conexión sqlite ya abierta (NO abre su propia DB — reusa index.db de StateStore).

ChromaDB (RESEARCH Pattern 4 + Pitfall 5, [CITED chromadb.dev]): PersistentClient(path=...). Una
colección por kb_id: `client.get_or_create_collection(name=kb_id, metadata={"hnsw:space":"cosine",
"embedding_model":..., "embedding_dim":768})`. upsert(ids, embeddings, documents, metadatas) con
embeddings PRECOMPUTADOS (de OllamaEmbeddingProvider) — ChromaDB no calcula nada. Usar PersistentClient,
NUNCA EphemeralClient. El client se inyecta por constructor (lo construye bootstrap).

Chunking (RESEARCH Chunking Strategy, D-33): texto/markdown/código 512 tokens + 10% overlap;
CSV/XLSX por fila o grupo de 10 filas, overlap 0. Token ~4 chars. Tokenizar por whitespace o
aproximar por chars (512 tokens ≈ 2048 chars). NO producir chunks de texto vacío (Pitfall 6).
