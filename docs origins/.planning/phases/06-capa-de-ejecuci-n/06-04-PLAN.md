<objective>
Build FileSystemAdapter (EXEC-02, EXEC-04, and the EXEC-03 mutation side): the Tool-port
adapter that performs real file I/O behind two mandatory gates — the SECOND WALL (D-68) and
POST-EXECUTION VERIFICATION (D-67) — and records an undo journal entry (D-65) before every
mutation.

Purpose: This is the phase's core security surface. CognitivePolicyEngine._normalize() calls
expanduser but NOT resolve() — so a symlink/`..` target can slip past the first policy pass.
The second wall closes this: the adapter calls Path(target).expanduser().resolve() (resolving
~/Data → /mnt/hdd/Data), reconstructs a single-step Plan wrapping the RESOLVED Action, re-runs
engine.evaluate, and blocks if the resolved level exceeds the adapter max_risk OR the resolved
path differs from the original. The engine is core.* (allowed import); we do NOT build a parallel
evaluator. Delete = send2trash (NOT unlink); journal.record runs BEFORE mutation so rollback works.
Output: src/execution/filesystem.py + verify/second-wall tests + a Tool-conformance check.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| confirmed plan → filesystem | a plan approved by first-pass policy may carry a symlink/`..` target that resolves elsewhere |
| adapter → real files | write/move/delete mutate the owner's 2 TB; verification is the only proof of correctness |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-path-tricks | Elevation of Privilege | execute() second wall | mitigate | Path(...).expanduser().resolve() resolves symlinks/`..` (engine only expanduser's); rebuilt resolved Action re-evaluated by CognitivePolicyEngine; block if resolved level > max_risk OR resolved != original. Closes Fase 1 01-RESEARCH §794 threat |
| T-verify-bypass | Spoofing | verify() | mitigate | per-type post-checks (write→size+sha256, move→dest∧¬src, delete→¬path∧in-trash); success is never marked on a failed verification |
| T-undo-corruption | Tampering | delete/move/overwrite mutation | mitigate | journal.record runs BEFORE every mutation; delete uses send2trash (recoverable) not unlink; overwrite backup captured to data/undo_backups before write |
| T-06-FS-EXDEV | Denial of Service | file.move across FS | accept→mitigate | shutil.move (not os.rename) handles NTFS↔ext4 EXDEV; grep-gate asserts os.rename count = 0 |
</threat_model>
