<objective>
Build ShellAdapter and GitAdapter (D-66, EXEC-01): execution adapters behind the `Tool` port
that run only allowlisted binaries/subcommands, via direct argv exec — NEVER shell=True. A
binary outside the TOML allowlist is rejected and audited (fail-closed). This closes the
shell-injection threat: with shell=False there is no shell expansion to inject into.

Purpose: GitAdapter reuses the exact subprocess pattern as ShellAdapter specialized for `git`,
so they are planned together (both request-response, no journal entries — shell commands are
not reversible; file mutations must go through FileSystemAdapter instead). Imports stay core.*
+ stdlib only (import-linter independence contract).
Output: src/execution/shell.py, src/execution/git.py + unit tests; one allowlist-violation error.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plan/action → subprocess | action.target/parameters carry the binary+args that become process argv |
| adapter → OS process | a spawned process runs with the daemon's privileges |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-shell-injection | Tampering | ShellAdapter/GitAdapter execute() | mitigate | argv exec via asyncio.create_subprocess_exec, NEVER shell=True (grep-gate asserts 0 occurrences); args passed as a list, no shell metacharacter expansion |
| T-06-ALLOW-1 | Elevation of Privilege | binary/subcommand off allowlist | mitigate | fail-closed: binary∉allowed_binaries (or sub∉allowed subcommands) → success=False + audit, process never spawned. No denylist, no sandbox (would contradict D-absoluto) |
| T-06-ALLOW-2 | Denial of Service | runaway/hung subprocess | mitigate | asyncio.wait_for timeout → proc.kill() + drain communicate() to avoid zombie |
</threat_model>
