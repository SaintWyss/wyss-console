<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| n8n (headless, LAN) → POST /api/intake | Cliente sin cookie-jar; input y credencial no confiables hasta validar bearer |
| /api/intake → daemon intake.propose | Cruza a la lógica de floor B (Plan 13-01) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-05 | Spoofing | request sin bearer haciéndose pasar por n8n | mitigate | `compare_digest(presented, intake_token)`; token_urlsafe(32) = ~256 bits; sin bearer válido → 401 |
| T-13-06 | Information Disclosure | leak del bearer en logs/audit | mitigate | `_LOG.warning` loguea SOLO el hecho + path del 401/429, JAMÁS el valor (espeja web.py líneas 156-162); el token no se imprime en consola ni va en URLs |
| T-13-07 | Spoofing (brute-force) | adivinar el bearer por fuerza bruta | mitigate | compare_digest (constante en tiempo) + rate limit propio (max_per_minute → 429) + entropía 256-bit |
| T-13-08 | Denial of Service | retry-storm / flood de n8n mal configurado | mitigate | Rate limit en memoria por minuto → 429; body cap (instruction max_length 2000) evita payloads gigantes |
| T-13-09 | Elevation of Privilege | relajar el middleware de cookie para "hacer andar n8n" | mitigate | Exención QUIRÚRGICA: solo `path == "/api/intake"` salta la cookie; host+origin siguen; ningún otro path pierde protección; test lo verifica |
| T-13-10 | Spoofing/SSRF | abuso desde fuera de la LAN | mitigate | Mismo bind del bridge (127.0.0.1 o --lan explícito) + Host allowlist intacta; el intake no abre binds nuevos |
| T-13-SC | Tampering | dependencias de package manager | accept | Este plan NO instala paquetes nuevos (rate limit y bearer con stdlib: secrets, collections); sin superficie de supply-chain |

## Invariante reforzado
El endpoint NUNCA usa ni deriva la cookie/web_token del pairing como credencial de intake, y JAMÁS
setea una cookie en la respuesta de /api/intake. Bearer y cookie son credenciales separadas y
rotables independientemente (borrar data/intake_token rota solo el intake).
