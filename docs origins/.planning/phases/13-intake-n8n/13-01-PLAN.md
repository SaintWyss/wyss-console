<objective>
Construir el corazón de seguridad del intake externo: un RPC nuevo del daemon `intake.propose`
que reusa el pipeline completo de `ask` (classify_intent → draft_plan → engine.evaluate) pero
FUERZA un floor de riesgo B antes del dispatch, garantizando que una fuente externa jamás
ejecute directo aunque la política resuelva nivel A. Más la config `[intake]` opt-in.

Purpose: INTAKE-02 — "toda propuesta de intake pasa por la política y cae a la bandeja como
B/C, jamás auto-ejecuta". La regla transversal inviolable del proyecto (nada B/C se
auto-ejecuta) se refuerza acá con una capa extra: para intake externo, ni siquiera A ejecuta.
Output: RPC `intake.propose` + sección de config `[intake]` + tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| n8n externo → daemon (vía web bridge, plan 13-02) | El contenido de `instruction` es input no confiable de terceros (email, forms, calendarios que n8n reenvía) |
| daemon → dispatch/pending_store | El plan cruza el gate determinístico CognitivePolicyEngine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Elevation of Privilege | intake.propose ejecutando directo un plan nivel A | mitigate | Floor B forzado (`max(decision.risk_level, B)`) ANTES de dispatch; la rama runner/_execute_plan de _ask NO se replica → intake nunca alcanza outcome "queued" |
| T-13-02 | Tampering | prompt-injection vía `instruction` externa laundering a un plan confiable | mitigate | La instrucción se audita rotulada como origen externo (actor SYSTEM/"intake", message "[intake externo]"); floor B/C + preview en bandeja = el owner sella; intake JAMÁS escribe a memoria (invariante Fase 11, ver abajo) |
| T-13-03 | Repudiation | acción externa sin rastro | mitigate | COMMAND_RECEIVED (SYSTEM/intake) + PLAN_CREATED + POLICY_DECISION + CONFIRMATION_REQUESTED auditados con task_id, actor distinguible del owner |
| T-13-04 | Elevation of Privilege | un plan D/REJECT externo bajado a ejecutable | mitigate | El floor SOLO sube (POL-04): D/REJECT pasa sin cambios por dispatch → "rejected" |

## Invariante documentado (decisión #6)
El contenido de intake JAMÁS se recuerda a memoria. La Fase 11 hardcodea el tier owner solo desde
MemoryTool gateado; `intake.propose` no toca el memory_store ni ningún path de escritura de memoria.
Esto previene el memory-poisoning / prompt-injection laundering (Pitfall 5/8 de RESEARCH). Cualquier
extensión futura que quiera persistir intake a memoria debe re-clasificar el trust tier explícitamente.
