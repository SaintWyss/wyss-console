<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archivos no confiables (2TB) → extractores | Los libs de parsing (pymupdf, openpyxl, Pillow) ejecutan sobre input arbitrario del owner |
| ruta CLI → scanner | `wyss index <ruta>` recibe un path que podría intentar traversal o symlink loop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Tampering | path traversal en scan(root) | mitigate | `Path.resolve()` del root + verificación de que es un directorio real antes de os.scandir (RESEARCH Security Domain) |
| T-03-13 | DoS | symlink loop de directorios | mitigate | D-42: el scanner NO sigue symlinks (entry.is_symlink() → skipped_symlink), evita loops infinitos |
| T-03-14 | DoS | archivo gigante agota memoria del extractor | mitigate | D-41: el scanner emite skipped_size sobre max_file_bytes (metadata-only); openpyxl read_only=True; sha256 por bloques |
| T-03-15 | Tampering/EoP | contenido de archivo tratado como instrucción | mitigate | V5: el extractor SOLO produce ExtractedContent (dato); el pipeline nunca ejecuta el texto. ffprobe corre con args fijos, sin shell=True |
| T-03-16 | Information Disclosure | password de PDF solicitado | mitigate | D-40: is_encrypted → UnsupportedFileError; NUNCA se pide ni se prueba password |
</threat_model>
